# Implementation Plan: Azure Infrastructure as Code

**Branch**: `modernization-fastapi-speckit` | **Date**: 2026-08-10 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/007-azure-terraform-iac/spec.md`

## Summary

Capture the eight confirmed application-owned Azure resources (`AI-103-Study-Lab` resource group and
its Cosmos DB, Azure SQL, and Azure AI Foundry resources) as a version-controlled Terraform
configuration. The workflow uses `aztfexport` to derive the configuration from the live environment,
then validates it with `terraform validate` and `terraform plan` — accepting zero planned changes as
the proof of correctness. No Azure resources are created, modified, or deleted.

## Technical Context

**Language/Version**: N/A — IaC tooling only; no application code changes

**Primary Dependencies**:
- `aztfexport` (Azure Export for Terraform — system-installed; version not pinned)
- Terraform CLI (system-installed; azurerm provider version determined by export)
- Azure CLI (system-installed; `az login` authentication)
- `azurerm` Terraform provider (version pinned in generated `main.tf` by aztfexport)

**Storage**: Local Terraform state (`terraform.tfstate`) during initial validation; remote backend
migration is deferred to a subsequent spec per Assumption 4 in the feature spec.

**Testing**: `terraform validate` (structural) + `terraform plan` (zero-change acceptance gate).
No pytest tests added — this spec adds no application code.

**Target Platform**: Developer workstation (macOS or Linux) with Azure CLI, aztfexport, and
Terraform CLI installed.

**Project Type**: Infrastructure as Code — brownfield capture, not greenfield provisioning.

**Performance Goals**: N/A — one-time export and validation workflow.

**Constraints**:
- Non-destructive: `terraform plan` MUST show zero additions, modifications, deletions, and
  replacements for all eight captured resources.
- No committed secrets: connection strings, access keys, and passwords MUST NOT appear in any
  committed file. Azure CLI authentication (`az login`) is the primary credential mechanism.
- Local state only: `terraform.tfstate` is excluded from version control for the duration of
  this spec.
- 8-resource boundary: only the explicitly confirmed application resources are captured.

**Scale/Scope**: 8 Azure resources across 1 resource group (`AI-103-Study-Lab`).

### Source Code (repository root)

The Terraform project is placed at `terraform/` in the repo root — separate from `infra/` (the
AZD/Bicep provisioning system). See Research Decision R-003 for rationale.

```text
terraform/
├── .gitignore                    # Excludes .terraform/, *.tfstate, *.tfstate.backup, terraform.tfvars, *.auto.tfvars
├── main.tf                       # terraform block + azurerm provider config (generated by aztfexport, then curated)
├── resource_group.tf             # azurerm_resource_group.AI-103-Study-Lab
├── ai_foundry.tf                 # Azure AI Hub (ai-brain-openai) + Azure AI Project (proj-default); known gaps documented here
├── cosmos_db.tf                  # azurerm_cosmosdb_account + azurerm_cosmosdb_sql_database + azurerm_cosmosdb_sql_container
├── sql.tf                        # azurerm_mssql_server + azurerm_mssql_database
├── variables.tf                  # subscription_id, tenant_id, location (no sensitive values)
├── outputs.tf                    # Resource IDs and endpoints for reference
├── terraform.tfvars.example      # Non-sensitive example variable values (committed)
└── known-gaps.md                 # Documented export gaps with manual workarounds and verification status
```

**Structure Decision**: `terraform/` at repo root, organized into 4 domain-specific resource files
after export. Single-file-per-resource output from aztfexport is reorganized before commit for
readability (SC-006). See Research Decision R-006.
